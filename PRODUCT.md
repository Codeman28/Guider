## Platform

web

(Desktop app: Tauri 2 shell rendering a web UI in WebView2 on Windows 10/11. The design language is web, not native.)

## Stack

Decided in SPEC §5: Tauri 2 + React + TypeScript + Vite, Tailwind CSS + Radix UI primitives, Zustand. The UI talks to the
Python engine sidecar over JSON-RPC 2.0 on stdio (no network port). Fonts are bundled locally (no CDN at runtime).

## Users

Primary (confirmed by the user): **Vietnamese secondary-school and university students** learning Microsoft 365 desktop
(Excel first, then Word and PowerPoint) for coursework and office-informatics exams. They ask in Vietnamese, often in
casual phrasing, sometimes without diacritics, and want a step-by-step guide that matches the Office they are looking at.
The wider audience in SPEC §1 (general Vietnamese Office users) remains in scope; students are the first target.

## Product Purpose

Guider answers "how do I do X in Excel?" by demonstrating it on the user's own Office: it opens a blank sandbox file, performs
the steps itself, captures each step, annotates the screenshot, writes a short Vietnamese guide, and cleans up. Success: the
learner finds every button exactly where the guide shows it, because the screenshots come from their own build, language,
DPI, theme and ribbon width.

## Positioning

Online tutorials show the author's screen. Guider's screenshots are taken on *this* machine, in *this* Office, at *this* window
width — "của chính bạn". Button labels and shortcuts in the text are the real strings read from UI Automation, never invented.

## Operating Context

- Windows 10/11, Microsoft 365 desktop, Excel in v1. Works offline with a local model (Ollama); cloud models are opt-in.
- A session: the user types a question in a narrow chat column (left, ~360px); Guider shows progress while an Excel window
  opens beside it and is driven for ~10–60 s; the tutorial opens as a tab on the right.
- While a demonstration runs the user must not type or click (Office closes menus when focus moves; ADR-0001). Esc stops it.
- Tutorials can be exported as Markdown, a single HTML file, or PDF.

## Capabilities and Constraints

- Demonstrations only in a blank sandbox document; never reads, lists or opens the user's files (SPEC §8).
- Never acts on File/Backstage, Account, Share, Save outside temp, Send, Sign-in, Trust Center, add-ins, macros, Copilot,
  network data features (SPEC §8, `engine/kem_engine/safety/blocklist.yaml`).
- Screenshots never leave the machine; the account avatar/name is redacted before saving.
- One-time consent screen on first run; a visible notice during every demonstration; "see what Guider did" opens the trace.
- Out-of-scope questions (download/install software, email, sharing, sign-in, macros) get a short text answer, no demo.
- A step Guider could not demonstrate is shown as text with "Bước này Guider chưa làm mẫu được trên máy bạn", never a wrong image.
- Learner mode: one step per screen with Next/Back (SPEC §9).
- Undecided: tutorial library organisation beyond a flat history list; Word/PowerPoint UI (Phase 4).

## Product Principles

1. **Your screen, not ours.** Every image and label comes from the learner's own Office; anything not demonstrated is said plainly.
2. **Privacy is the default, not a setting.** Local model first, nothing uploaded, the user's files untouched.
3. **Transparent control.** The learner always knows when Guider is driving Excel, can stop it with Esc, and can see what it did.
4. **One action per step.** Guides read like a calm tutor beside you, in plain Vietnamese.

## Accessibility & Inclusion

WCAG 2.2 AA (confirmed): sufficient contrast in light and dark themes, full keyboard operation (including Esc to stop and
Next/Back in learner mode), screen-reader labels, visible focus, text that survives long Vietnamese strings and long Office
button names without truncation.
